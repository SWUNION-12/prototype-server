# 실습 준비·오류 해결 도우미 프로토타입 설계

- 작성일: 2026-11-04
- 원본 PRD: https://app.notion.com/p/itzjb/PRD-40e265ad31ba80938f32f1c2361d36ca (2026 연합 해커톤 / 주제 12)
- 이 문서는 PRD를 대체하지 않습니다. PRD의 P0·P1 범위를 실제로 돌아가게 만들 때 필요한 결정만 추가로 적습니다. 문서에 없는 요구사항은 PRD를 따릅니다.

## 1. 목적

해커톤 팀이 PRD의 핵심 기능을 실제 실행으로 확인할 수 있는 프로토타입을 만듭니다. 화면 완성도보다 기능 동작이 우선입니다.

사용자 요청: "UI는 신경 쓰지 않는다. 핵심 기능이 제대로 동작하는지 확인하고 싶다."

## 2. 목표, 비목표, 실패 기준

### 목표

PRD 9장 시연 성공 기준을 이 Mac에서 실제 실행으로 통과합니다. Windows 실기기 항목은 제외하고, 확인하지 못한 상태로 보고합니다.

1. 강사가 파이썬 버전과 패키지를 입력하면 lock 파일과 수업 이미지가 만들어진다.
2. 학생 2명이 각자의 컨테이너와 code-server에 동시에 접속한다.
3. 학생이 패키지를 지우면 주기 점검이 감지하고, 에이전트가 복구하고, 서버 재점검을 통과한다.
4. 대시보드에 접속 여부, 환경 상태, 에이전트 조치 내역, 강사 도움 필요가 나온다.
5. 에이전트가 고치지 못하는 문제는 강사 도움 필요로 넘어간다.
6. Mac에서 버전 조회, 설치, 검증이 성공한다. 실패하면 대시보드에 표시된다.
7. 코드 오류 도움 요청에 정답 코드 없이 설명을 준다. (P1)
8. 같은 오류 유형이 여러 번 들어오면 대시보드에 집계된다. (P1)
9. 오류 내용에 인젝션 문구를 넣어도 에이전트가 허용 목록 밖의 동작을 실행하지 못한다.

### 비목표

- 화면 디자인. 정적 HTML과 최소한의 JavaScript로만 만듭니다.
- PRD 3장 "제외" 표의 항목 전부.
- 운영 수준 보안(gVisor, 외부 네트워크 차단), 배포, 부하 측정.
- MySQL 연동. 프로토타입은 H2 파일 DB를 쓰고, JPA로 작성해 나중에 MySQL로 바꿉니다.

### 실패로 보는 경우

- 시연은 되지만 실제로는 하드코딩이나 가짜 응답으로 돌아가는 경우. 컨테이너, 점검, 복구, 설치 검증은 전부 실제 실행이어야 합니다.
- 에이전트가 "고쳤다"고 말했다는 이유로 해결로 기록하는 경우. 해결 여부는 서버 재점검 결과로만 정합니다.
- 에이전트가 학생 코드를 수정하거나 정답 코드를 보여주는 경우.

## 3. 사용자가 정한 것

- 서버 스택: **Spring Boot** (PRD 확정 스택. 해커톤에서 이어서 개발)
- LLM: **Anthropic API, 사용자가 키를 직접 제공**. 키는 프로젝트 루트 `.env`에 이미 있습니다. 변수 이름이 `ANTROPHIC_API_KEY`(철자 다름)이므로 서버는 `ANTHROPIC_API_KEY`를 먼저 찾고 없으면 이 이름을 읽습니다. `.env` 파일은 수정하지 않고, 키 값은 로그나 화면에 출력하지 않습니다.
- UI 완성도: 신경 쓰지 않음

## 4. 구성

```
강사 브라우저 ──┐
학생 브라우저 ──┼─> Spring Boot 서버 (H2, 정적 HTML)
                │        │ docker-java
                │        v
                │   Docker Desktop ── 학생별 컨테이너 (code-server + uv 환경 + 코드 볼륨)
                │        ^
학생 PC 터미널 ─┘  (설치 스크립트, lock 파일, 코드 zip 다운로드)
                         서버 ──> LLM API (에이전트 호출 때만)
```

- 서버만 Docker 소켓에 접근합니다. 학생 컨테이너에는 소켓을 넣지 않습니다.
- 서버 호스트에 필요한 것: Java, Docker, uv (`uv lock` 실행용)

## 5. 기능별 설계

### 5.1 기본 이미지

`swunion/lab-base` 이미지를 한 번 빌드합니다.

- `codercom/code-server` 기반, `coder` 사용자(비루트)로 실행
- uv 바이너리 포함
- Open VSX의 `ms-python.python` 확장 설치 (PRD 13장 검증 항목, 설치 가능 여부를 빌드 때 확인)
- 경로 규칙
  - `/opt/lab/spec`: 수업 스펙 원본(`pyproject.toml`, `uv.lock`, `.python-version`). root 소유, 학생은 읽기만 가능
  - `/opt/venv`: 학생이 쓰는 가상환경. 학생이 패키지를 지우는 시연을 위해 `coder` 소유
  - `/opt/uv-python`: uv가 설치한 파이썬. root 소유
  - `/opt/uv-cache`: uv 캐시. 이미지에 남겨 복구를 빠르게 하고 네트워크 없이도 돌게 함
  - `/home/coder/project`: 학생 코드. 세션별 Docker 볼륨
- 터미널의 `python`과 VS Code 기본 인터프리터가 `/opt/venv/bin/python`을 가리키게 설정
- 스펙 원본을 학생 폴더 밖에 두는 이유: 학생이 `uv remove` 등으로 프로젝트 파일을 바꿔도 복구 기준이 바뀌지 않게 하려는 것

### 5.2 환경 발급 (ENV-1~4)

`POST /api/courses` 입력: 수업명, 파이썬 버전, 패키지 목록

1. 형식 검사
   - 파이썬 버전: `3.X` 또는 `3.X.Y`
   - 패키지: 한 줄에 하나, `이름`, `이름==버전`, `이름>=버전`만 허용. 이름은 PEP 508 이름 규칙
2. 서버가 `pyproject.toml`과 `.python-version`을 만들고 `uv lock`을 실행합니다.
3. `uv lock`이 실패하면 오류 원문 요약을 강사에게 보여주고 상태를 `FAILED`로 둡니다. (ENV-3)
4. 성공하면 기본 이미지 위에 스펙을 복사하고 `uv sync --frozen`을 실행하는 수업 이미지를 빌드합니다.
5. 빌드가 끝나면 임시 컨테이너에서 설치된 패키지 목록을 뽑아 **기준 목록**으로 저장합니다. 점검은 이 목록과 비교합니다. universal lock에는 Windows 전용 패키지 같은 다른 플랫폼 항목이 섞여 있어서, lock 파일을 직접 비교하면 오탐이 납니다.
6. 상태: `LOCKING` → `BUILDING` → `READY` 또는 `FAILED`. 비동기로 처리하고 강사 화면이 상태를 조회합니다.
7. `READY`가 되면 6자리 입장 코드를 발급합니다.

수업 중 스펙 변경은 지원하지 않습니다. (PRD 제안)

### 5.3 학생 입장과 컨테이너 (LAB-1~6)

`POST /api/join` 입력: 입장 코드, 표시 이름

- 세션 토큰(무작위 32바이트)을 발급합니다. 학생 화면 URL과 학생 API는 이 토큰으로 접근합니다.
- 컨테이너 생성
  - 수업 이미지, 볼륨 `lab-{세션ID}`를 `/home/coder/project`에 연결
  - code-server 비밀번호를 세션마다 무작위로 생성해 환경변수로 전달
  - 포트: 컨테이너 8080을 호스트의 무작위 포트에 연결. 기본은 `127.0.0.1`에만 열고, 설정으로 LAN에 열 수 있게 함
  - 제한: 메모리 1GB, CPU 1개, 프로세스 256개
  - 재시작 정책 없음. IDE 중단을 점검과 에이전트가 처리하는 흐름을 보여주기 위함
- code-server의 `/healthz`가 응답할 때까지 기다리고, 걸린 시간을 기록합니다. (PRD 11장 리스크 측정용)
- 학생 화면에 IDE 주소와 비밀번호를 보여줍니다.
- 세션 분리(LAB-4)는 세션별 포트와 비밀번호로 처리합니다. PRD의 리버스 프록시 방식은 프로토타입에서 쓰지 않습니다. 이 방식의 한계는 같은 호스트에 접근할 수 있는 사람이 포트를 알면 로그인 화면까지는 볼 수 있다는 점입니다.

### 5.4 주기 점검 (AGT-1, DASH-1, DASH-2)

서버가 15초마다(설정 가능) 실행 중인 세션을 일반 코드로 점검합니다. LLM을 쓰지 않습니다.

| 항목 | 방법 |
| --- | --- |
| 컨테이너 실행 여부 | Docker inspect |
| IDE 접속 여부 | 컨테이너 안 `/proc/net/tcp`에서 8080 포트의 ESTABLISHED 연결 수 |
| 파이썬 버전 | `/opt/venv/bin/python`으로 버전 출력 |
| 패키지 | `uv pip list --python /opt/venv/bin/python --format json` |

판정
- 기준 목록의 패키지가 없음: `MISSING`
- 버전이 다름: `VERSION_MISMATCH`
- 파이썬 버전이 다름: `PYTHON_MISMATCH`
- 컨테이너나 IDE가 중단됨: `IDE_DOWN`
- 기준 목록에 없는 패키지: `EXTRA`. 경고만 하고 정상으로 봅니다. (PRD 미정 사항 기본안)

`EXTRA`를 뺀 불일치가 있으면 에이전트를 호출합니다. 같은 불일치로 이미 강사 도움 필요가 된 세션은 다시 호출하지 않습니다. LLM 비용과 무한 반복을 막기 위함입니다.

### 5.5 복구 에이전트 (AGT-2~7)

세션마다 한 번에 하나의 실행만 돌립니다. 호출 원인은 `CHECK`(점검 불일치) 또는 `HELP`(도움 버튼)입니다.

LLM에 넘기는 내용
- 수업 스펙(파이썬 버전, 패키지)
- 최신 점검 결과(구조화된 값)
- 도움 요청이면 학생이 붙인 오류 내용. 최대 4,000자로 자르고 "신뢰하지 않는 데이터" 태그로 감쌉니다.
- 서버가 정규식으로 뽑은 오류 유형(`ModuleNotFoundError` 등)

도구 허용 목록. 서버가 정해진 동작만 실행하고, 인자로 명령어나 경로를 받지 않습니다.

| 도구 | 서버가 실제로 하는 일 |
| --- | --- |
| `check_environment` | 5.4 점검을 실행하고 결과 반환 |
| `restore_packages` | `/opt/lab/spec` 기준 `uv sync --frozen --inexact` 실행. `--inexact`로 학생이 추가한 패키지는 지우지 않음 |
| `restart_ide` | 컨테이너 재시작 후 `/healthz` 확인 |
| `explain_to_student` | 학생에게 설명 전달. 인자: 오류 의미, 확인할 곳 |
| `escalate_to_instructor` | 강사 도움 필요로 표시. 인자: 이유 |
| `finish` | 실행 종료. 인자: 판단 유형(`ENV`, `CODE`, `OUT_OF_SCOPE`), 요약 |

규칙
- 목록에 없는 도구 이름이나 정해지지 않은 인자가 오면 실행하지 않고 거부 기록을 남깁니다.
- 한 번 실행에 LLM 호출은 최대 6회입니다.
- `explain_to_student`의 텍스트에서 코드 블록은 서버가 지웁니다. 정답 코드 차단을 프롬프트에만 맡기지 않기 위함입니다.
- LLM 호출이 실패하면 1회 재시도하고, 그래도 실패하면 강사 도움 필요로 넘깁니다.
- 실행이 끝나면 서버가 다시 점검합니다. 환경 불일치가 남아 있으면 LLM 판단과 상관없이 강사 도움 필요로 기록합니다. (AGT-4, AGT-5)
- 모든 실행을 `AgentAction`으로 저장합니다. 원인, 판단 유형, 호출한 도구와 결과, 재점검 결과, 최종 처리(해결, 설명, 강사 전달), 요약. (AGT-7)
- 컨테이너 안에서 실행하는 점검과 복구 명령은 전부 `coder` 사용자로 실행합니다. root로 실행하지 않습니다. 에이전트 권한을 학생 권한보다 크게 두지 않기 위함입니다.

### 5.5.1 "에이전트가 못 고치는 문제" 시연 (목표 5)

가짜 장애 스위치 없이 실제 상황 두 가지로 보여줍니다.

1. **점검 경로, 결정적:** 학생 터미널에서 패키지를 지운 뒤 가상환경 쓰기 권한을 없앱니다(`chmod -R a-w /opt/venv`). `coder`로 실행하는 복구가 권한 오류로 실패하고, 재점검도 실패하므로 서버가 강사 도움 필요로 기록합니다. 통합 테스트도 이 시나리오로 씁니다.
2. **도움 요청 경로, LLM 판단:** 스펙 밖 요청("노트북 와이파이가 안 돼요", "torch도 깔아 주세요")을 보내면 에이전트가 `OUT_OF_SCOPE`로 판단해 강사에게 넘깁니다. LLM 판단에 기대므로 실제 키로 시연 전에 확인합니다.

### 5.6 도움 요청과 강사 호출 (P0 버튼, P1 설명)

- `POST /api/s/{token}/help`: 오류 내용(선택)을 받아 `HelpRequest`를 저장하고 에이전트를 호출합니다. 학생 화면은 결과를 조회해 설명이나 처리 상태를 보여줍니다.
- `POST /api/s/{token}/escalate`: 강사 도움 필요로 표시합니다. 이유는 "학생 호출".
- 오류 유형은 서버가 정규식으로 뽑습니다. 반복 오류 집계(DASH-5)는 이 값으로 세고, LLM 판단에 의존하지 않습니다.

### 5.7 로컬로 이어가기 (LOC-1~7)

1. 학생이 Mac 또는 Windows를 고르면 버전 조회 명령어를 보여줍니다. 출력 형식은 PRD 제안 그대로이며, 경로·사용자 이름·컴퓨터 이름은 출력하지 않습니다.

   ```txt
   os=macos
   arch=arm64
   python=3.12.4
   ```

   | 키 | 허용 값 | 비고 |
   | --- | --- | --- |
   | `os` | `macos`, `windows` | |
   | `arch` | `arm64`, `x86_64` | Mac은 `uname -m` 값 그대로. Windows 명령어가 `AMD64`는 `x86_64`로, `ARM64`는 `arm64`로 바꿔 출력 |
   | `python` | `X.Y.Z` 또는 `none` | 파이썬이 없거나 Windows 스토어 별칭만 있으면 `none` |

2. 학생이 출력을 붙여넣으면 서버가 세 줄을 위 형식으로만 검사합니다. 앞뒤 공백과 빈 줄은 무시하고, 다른 줄이 섞이면 거부합니다. 통과한 값만 저장하고, 원문은 설치 명령어나 에이전트에 넣지 않습니다. 학생이 고른 OS와 `os` 값이 다르면 거부합니다.
3. 서버가 OS별 설치 명령어를 줍니다.
   - Mac: `curl -fsSL {서버}/l/{token}/install.sh | sh`
   - Windows: `powershell -ExecutionPolicy ByPass -c "irm {서버}/l/{token}/install.ps1 | iex"`
   - 실행 전에 볼 수 있게 스크립트 주소도 함께 보여줍니다.
4. 설치 스크립트 동작은 PRD 제안 그대로입니다. uv 확인과 설치 → 스펙 파일 3개와 `verify.py` 다운로드 → `uv sync --frozen` → `uv run python verify.py`. 설치 폴더는 기본 `~/swunion-{수업}`이고 환경변수로 바꿀 수 있습니다.
5. `verify.py`는 직접 지정한 패키지마다 설치 버전을 lock과 비교하고 실제로 import합니다. 패키지 이름과 import 이름이 다른 경우(`scikit-learn`과 `sklearn` 등)는 `importlib.metadata`로 모듈 이름을 찾습니다. 출력은 `verify=ok` 또는 `verify=fail`과 실패 항목입니다.
6. 학생이 검증 출력을 붙여넣습니다. (PRD 미정 사항 기본안) 실패면 강사 도움 필요로 표시하고, 학생 화면에 클라우드 실습을 이어가라고 안내합니다.
7. 코드 zip은 설치와 별도로 받습니다. (PRD 미정 사항 기본안) 서버가 컨테이너의 `/home/coder/project`를 tar로 받아 zip으로 바꾸고, `.venv`, `__pycache__`, `.ipynb_checkpoints`, `.pytest_cache`, `.mypy_cache`, `*.pyc`를 뺍니다.

### 5.8 강사 대시보드 (DASH-1~5)

`GET /api/courses/{id}/dashboard`가 JSON을 주고, 강사 화면이 3초마다 조회합니다.

- 학생별: 이름, 컨테이너 실행, IDE 접속, 클라우드 환경 상태와 불일치 항목, 추가 패키지 경고, 로컬 설치 상태, 강사 도움 필요와 이유, 최근 에이전트 조치
- 수업 전체: 반복 오류 유형별 건수. 화면에 "도움 버튼을 누른 학생 기준이며 전체 오류 수가 아님"을 표시합니다.
- 강사가 도움 필요를 처리 완료로 바꿀 수 있습니다.
- `POST /api/courses/{id}/end`: 수업의 모든 컨테이너를 중단합니다. 볼륨은 남깁니다.

### 5.9 강사 인증

강사 데모 계정 하나를 둡니다. (PRD 미정 사항 기본안) 강사 화면과 강사 API에 HTTP Basic 인증을 겁니다.

### 5.10 설정값 출처

`.env`에는 API 키 한 줄만 있고, 이 파일은 수정하지 않습니다. 나머지 설정은 `application.yml`에 기본값을 두고, 환경변수나 `.env`에 같은 이름이 있으면 그 값을 씁니다.

| 설정 | 기본값 | 비고 |
| --- | --- | --- |
| `INSTRUCTOR_USERNAME`, `INSTRUCTOR_PASSWORD` | `instructor` / `instructor` | 로컬 시연용. LAN에 열 때는 바꿔야 함 |
| `LLM_MODEL` | 빠르고 저렴한 Anthropic 모델 | 구현 시점의 모델 ID로 고정 |
| `CHECK_INTERVAL_SECONDS` | 15 | |
| `PUBLIC_BASE_URL` | `http://localhost:8080` | 학생 PC가 서버에 접근하는 주소 |
| `IDE_BIND_ADDRESS` | `127.0.0.1` | LAN 시연 때 `0.0.0.0` |

## 6. 데이터와 API

### 엔티티 (PRD 7장 + 추가 필드)

| 엔티티 | PRD 주요 필드 | 프로토타입 추가 필드 |
| --- | --- | --- |
| Course | 수업명, 파이썬 버전, 패키지 목록, lock 파일, 입장 코드, 상태 | 오류 요약, 이미지 이름, 기준 패키지 목록 |
| StudentSession | 학생 표시 이름, 컨테이너 ID, IDE 접속 정보, 마지막 접속, 환경 상태 | 세션 토큰, 호스트 포트, code-server 비밀번호, 시작 소요 시간, 강사 도움 필요 여부와 이유 |
| EnvironmentCheck | 세션, 점검 시각, 결과, 불일치 항목 | 추가 패키지 경고 |
| LocalInstall | 세션, OS, CPU, 파이썬 버전, 검증 결과 | 검증 실패 항목 |
| HelpRequest | 세션, 오류 유형, 오류 내용, 처리 상태, 강사 호출 여부 | 학생에게 전달한 설명 |
| AgentAction | 세션, 호출 원인, 판단 결과, 실행 도구, 재점검 결과 | 최종 처리, 요약, 거부된 도구 호출 |

`EnvironmentCheck`는 15초마다 쌓이면 금방 커지므로, 세션의 최신 상태는 `StudentSession`에 갱신하고 `EnvironmentCheck` 행은 결과가 바뀔 때만 추가합니다.

### API (PRD 7장 기준)

| Method | PRD 경로 | 프로토타입 경로 | 용도 |
| --- | --- | --- | --- |
| POST | `/courses` | `/api/courses` | 수업 생성 및 환경 발급 (강사 인증) |
| GET | 없음 | `/api/courses/{id}` | 발급 상태 조회 (강사 인증) |
| POST | `/courses/{id}/sessions` | `/api/join` | 입장 코드와 이름으로 입장, 컨테이너 생성 |
| GET | `/courses/{id}/dashboard` | `/api/courses/{id}/dashboard` | 대시보드 (강사 인증) |
| POST | 없음 | `/api/courses/{id}/end` | 수업 종료 (강사 인증) |
| GET | 없음 | `/api/s/{token}` | 학생 세션 상태, IDE 주소, 최근 도움 결과 |
| POST | `/sessions/{id}/help` | `/api/s/{token}/help` | 도움 요청 |
| POST | `/sessions/{id}/escalate` | `/api/s/{token}/escalate` | 강사 호출 |
| POST | `/sessions/{id}/local/diagnostics` | `/api/s/{token}/local/diagnostics` | 버전 조회 결과 제출 |
| GET | `/sessions/{id}/local/install` | `/api/s/{token}/local/install?os=` | OS별 조회·설치 명령어 |
| POST | 없음 | `/api/s/{token}/local/verify` | 설치 검증 결과 제출 |
| GET | `/sessions/{id}/code.zip` | `/l/{token}/code.zip` | 코드 다운로드 |
| GET | 없음 | `/l/{token}/install.sh`, `/l/{token}/install.ps1`, `/l/{token}/files/{이름}` | 설치 스크립트와 스펙 파일 |

학생 API는 세션 ID 대신 세션 토큰을 경로에 씁니다. 세션 ID를 추측해 남의 세션에 접근하는 것을 막기 위함입니다. 학생 입장을 `/api/join`으로 바꾼 이유는 학생이 수업 ID가 아니라 입장 코드만 알기 때문입니다.

## 7. 검증 계획

보고할 때 세 가지를 나눠 적습니다.

1. **자동 테스트**
   - 입력 형식 검사(파이썬 버전, 패키지, 버전 조회 출력, 검증 출력)
   - 점검 비교 로직
   - 에이전트 루프: 가짜 LLM으로 허용 목록 밖 도구, 정해지지 않은 인자, 코드 블록 포함 설명, LLM 실패를 각각 넣어 거부와 강사 전달을 확인
   - Docker 통합 테스트: 작은 패키지 조합으로 발급 → 학생 2명 입장 → 패키지 삭제 → 감지 → 복구 → 재점검 통과
2. **빌드와 실행**: 서버 빌드, 이미지 빌드, 컨테이너 시작 시간 측정
3. **실제 시연 흐름**
   - 이 Mac에서 실제 LLM 키로 감지, 복구, 대시보드 표시 확인
   - 브라우저로 학생 2명 IDE 동시 접속 확인
   - 이 Mac에서 설치 스크립트 실행과 검증
   - 오류 내용에 인젝션 문구를 넣은 실제 LLM 호출
   - Windows 실기기: 확인 불가. 명령어와 스크립트만 만들고 "미확인"으로 보고

## 8. 제가 정한 것 (사용자 확인 필요)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| DB | H2 파일 DB, JPA 사용 | MySQL 설치 없이 바로 실행. 나중에 교체 |
| 빌드 도구 | Gradle, Java 21 대상 | 팀원 JDK가 21 이상이면 빌드 가능 |
| 화면 | Spring Boot 정적 HTML + 바닐라 JS | UI 비중이 낮음 |
| 세션 분리 | 세션별 포트 + 비밀번호 | 리버스 프록시의 WebSocket 처리 부담을 피함 |
| 점검 기준 | lock 파일 대신 이미지 빌드 직후 설치 목록 | universal lock의 다른 플랫폼 패키지 오탐 방지 |
| 복구 명령 | `uv sync --frozen --inexact`, 원본 스펙 사용 | 학생 추가 패키지 보존, 학생이 바꾼 파일 무시 |
| 점검 주기 | 15초 | 시연 대기 시간 단축. 설정으로 변경 |
| 반복 호출 방지 | 같은 불일치로 강사 전달된 세션은 재호출 안 함 | 비용과 무한 반복 방지 |
| 컨테이너 안 실행 사용자 | 점검·복구 모두 `coder` | 에이전트 권한을 학생 권한 이하로 제한 |
| 못 고치는 문제 시연 | 가상환경 권한 제거(결정적) + 스펙 밖 도움 요청(LLM 판단) | 가짜 장애 스위치 없이 실제 상황으로 시연 |
| 강사 계정 | `instructor` / `instructor` 기본값, 환경변수로 변경 | `.env`를 수정하지 않기 위함 |
| 버전 조회 값 | `os`: macos·windows, `arch`: arm64·x86_64, `python`: X.Y.Z·none | PRD 예시 형식을 기준으로 허용 값만 확정 |
| LLM 호출 방식 | Anthropic Messages API의 tool use를 HTTP로 직접 호출. `LlmClient` 인터페이스 뒤에 두어 제공사 교체 가능 | PRD "서버에서 교체할 수 있게 분리" |
| LLM 모델 | 빠르고 저렴한 모델을 기본값으로, `.env`의 `LLM_MODEL`로 변경 가능 | 도구 선택 위주의 짧은 호출이라 지연과 비용이 더 중요 |
