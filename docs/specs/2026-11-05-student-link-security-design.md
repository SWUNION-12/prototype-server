# 학생 주소 보안 설계

- 작성일: 2026-11-05
- 기준 문서: `docs/specs/2026-11-05-client-adoption-design.md`. 여기 없는 내용은 기준 문서와 현재 코드를 따른다.

## 1. 왜 하는가

학생 실습 화면 주소 `/lab?t=<토큰>`은 그 자체가 열쇠다. 주소를 받은 사람은 IDE 비밀번호를 보고 그 학생의 IDE에 들어가고, 코드 zip을 받고, 도움 요청과 강사 호출을 보낼 수 있다. 주소는 메신저 공유, 화면 공유, 캡처, 브라우저 기록으로 쉽게 샌다.

## 2. 사용자가 정한 것

| 항목 | 결정 |
| --- | --- |
| 1. 주소에서 토큰 빼기 | 입장하면 서버가 학생 쿠키를 주고, 주소는 `/lab`만 쓴다. 공유된 주소로는 "다시 입장" 화면만 나온다. |
| 2. IDE 비밀번호 없애기 | Caddy가 `/ide/<포트>/` 요청마다 서버에 주인 학생인지 묻고 아니면 막는다. code-server는 비밀번호 없이 돈다. |
| 범위 | 1, 2를 한 번에 한다. IP·기기 고정은 하지 않는다. |

## 3. 실패로 보는 경우

- 학생 화면 주소, IDE 주소, 설치 명령 주소 중 어느 하나만으로 다른 사람이 그 학생의 IDE·코드·도움 요청에 닿는 경우
- 운영(Caddy 뒤)에서 IDE 포트가 비밀번호도 확인도 없이 열리는 경우
- 로컬·LAN 시연(Caddy 없음)에서 IDE가 비밀번호 없이 열리는 경우
- 다른 사이트가 학생 브라우저로 도움 요청·강사 호출을 보낼 수 있는 경우(CSRF)
- IDE 안 실습 도우미 패널(`/api/ide/**`, 헤더 키)이 깨지는 경우

## 4. 설계

### 4-1. 학생 쿠키

| 항목 | 내용 |
| --- | --- |
| 쿠키 | `LAB_STUDENT`. 값은 지금의 세션 토큰. HttpOnly, SameSite=Strict, HTTPS 요청이면 Secure, Path `/`, 유지 12시간 |
| 발급 | `POST /api/join` 성공(새 입장 201, 재입장 200) 때. 응답 본문에는 토큰을 싣지 않는다. 재입장은 지금처럼 토큰을 바꾸므로 예전 브라우저의 쿠키는 무효가 된다. |
| 학생 API | `/api/s/{token}/**`를 `/api/me/**`로 바꾼다(`GET /api/me`, `POST /api/me/help`, `POST /api/me/escalate`, `GET /api/me/local/install`, `POST /api/me/local/diagnostics`, `POST /api/me/local/verify`, `GET /api/me/code.zip`). 쿠키가 없거나 무효면 404 `{error}`. 토큰 경로 API는 지운다. |
| 나가기 | `POST /api/me/logout` → 쿠키를 지운다(204). 화면 머리말에 "나가기". |
| CSRF | `/api/me/**`의 POST는 강사 쪽과 같은 `XSRF-TOKEN` 쿠키 → `X-XSRF-TOKEN` 헤더로 검사한다. `/api/join`은 PIN이 있어 제외한다(작업 중 정함). `/api/ide/**`는 지금처럼 제외. |
| 한 브라우저 한 학생 | 같은 브라우저에서 다른 학생이 입장하면 쿠키가 바뀐다. 시연에서는 학생마다 다른 브라우저나 시크릿 창을 쓴다. |

### 4-2. 내 PC로 이어가기 링크

터미널(curl, PowerShell)은 쿠키가 없다. 화면이 "내 PC로 이어가기"를 열 때 서버가 **10분 동안만 쓰는 다운로드 코드**를 만든다. 설치 명령과 스크립트·파일·zip 주소는 `/l/<다운로드 코드>/…`를 쓴다. 코드는 세션 토큰과 다른 무작위 값이고, 10분이 지나거나 재입장으로 토큰이 바뀌면 쓸 수 없다. 서버 메모리에 둔다(서버를 다시 켜면 다시 받는다). 화면의 코드 zip 버튼은 쿠키로 받는 `GET /api/me/code.zip`을 쓴다.

### 4-3. IDE 접근 확인

| 항목 | 내용 |
| --- | --- |
| 방식 설정 | `lab.ide-auth`(`IDE_AUTH`): `password`(기본, 로컬·LAN) 또는 `proxy`(운영, Caddy 뒤) |
| proxy 방식 컨테이너 | 컨테이너를 만들 때 code-server 실행 인자를 `--auth none`으로 바꾼다(기본 이미지는 그대로). 세션마다 만든 방식을 기록한다. |
| password 방식 | 지금과 같다. 화면에 IDE 비밀번호가 보인다. |
| 확인 API | `GET /api/ide-auth/{port}`: `LAB_STUDENT` 쿠키의 세션이 그 포트의 주인이면 204, 아니면 401. 본문은 짧은 안내 문구. |
| Caddy | `/ide/<포트>/` 경로에 `forward_auth 127.0.0.1:8080 { uri /api/ide-auth/<포트> }`. 통과한 요청에서 `JSESSIONID`, `XSRF-TOKEN`, `LAB_STUDENT`를 Cookie에서 빼고 code-server로 넘긴다(Caddy 2.6.2에서 확인한 빈 값 아닌 치환 규칙). |
| 화면 | `GET /api/me`는 password 방식 세션에만 `idePassword`를 싣는다. proxy 방식이면 IDE iframe이 바로 열리고 비밀번호 칸이 없다. |
| 예전 컨테이너 | proxy 방식으로 바꾸기 전에 만든 컨테이너는 비밀번호 방식 그대로라 화면에 비밀번호가 보이고, Caddy 확인도 함께 받는다. |

## 5. 하지 않는 것

- 강사가 학생 IDE를 여는 기능
- IP·기기 고정
- IDE를 하위 도메인으로 옮기는 것(같은 출처 문제는 알려진 한계로 남는다)

## 6. 확인 방법

- 서버 단위 테스트: 쿠키 발급·속성, `/api/me/**` 쿠키 없으면 404, 재입장 뒤 옛 쿠키 404, CSRF, 다운로드 코드 10분 만료·재입장 무효, `/api/ide-auth` 주인 204·남 401·쿠키 없음 401, proxy 방식 컨테이너 인자 `--auth none`, `idePassword`는 password 방식에만.
- Caddy: `caddy:2.6.2` 이미지로 forward_auth와 쿠키 제거를 실제로 돌려 본다.
- 브라우저: 입장 → `/lab`(주소에 토큰 없음) → IDE가 비밀번호 없이 열림(proxy) → 다른 브라우저에 `/lab`과 IDE 주소를 붙여 넣으면 막힘 → 나가기.
