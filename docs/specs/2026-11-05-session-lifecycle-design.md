# 수업·세션 수명 관리 설계

- 작성일: 2026-11-05
- 기준 문서: `docs/specs/2026-11-04-prototype-design.md` (이하 "기존 스펙"). 여기 없는 내용은 기존 스펙과 현재 코드를 따른다.
- 대상 코드: https://github.com/SWUNION-12/prototype-server (main)

## 1. 왜 만드는가

지금 프로토타입은 수업과 세션을 만들기만 하고 되돌리거나 치우지 못한다.

- 학생이 학생 화면 탭을 닫으면 세션 토큰을 잃는다. 같은 이름으로 다시 입장하면 새 컨테이너가 하나 더 생기고, 원래 코드는 주인 없이 남는다.
- 수업을 종료하면 되돌릴 방법이 없다.
- 끝난 수업의 컨테이너, 볼륨, 이미지를 지우는 기능이 없다. 지금은 `docker rm`을 직접 쳐야 한다.
- 중복 입장으로 생긴 학생 행이나 고장 난 컨테이너를 강사가 하나씩 다룰 수 없다.

해커톤 시연 중에 학생이 창을 닫는 일은 흔하다. 이 문제가 가장 급하다.

## 2. 사용자가 정한 것

| 항목 | 결정 |
| --- | --- |
| 세션 되찾기 | 어느 브라우저, 어느 PC에서든 **입장 코드 + 이름 + PIN**으로 원래 세션에 돌아온다. 브라우저에 토큰을 기억하는 기능은 만들지 않는다. |
| PIN 초기화 | 강사가 대시보드에서 학생 PIN을 초기화할 수 있다. |
| 수업 재개 | 끝난 수업을 재개하면 수업이 READY로 돌아가고, 학생 컨테이너를 **전부 즉시** 다시 켠다. |
| 수업 삭제 | 끝난 수업만 지울 수 있다. 컨테이너, 볼륨(학생 코드), 수업 이미지, DB 기록까지 **통째로** 지운다. 수업 이름을 직접 입력해야 실행된다. |
| 학생 개별 관리 | 강사가 학생 한 명의 **컨테이너 재시작**과 **학생 삭제**를 할 수 있다. |
| 만들지 않는 것 | 학생 개별 컨테이너 정지, 유휴 컨테이너 자동 정지, 삭제 전 코드 일괄 다운로드, 브라우저 토큰 기억 |

## 3. 목표와 실패 기준

### 목표

1. 학생이 탭을 닫거나 다른 PC로 옮겨도 입장 코드, 이름, PIN으로 원래 컨테이너와 코드에 돌아온다.
2. PIN을 잊은 학생은 강사가 초기화한 뒤 새 PIN을 정하고 원래 코드로 돌아온다.
3. 강사가 끝난 수업을 재개하면 학생들이 원래 코드 그대로 실습을 이어 간다.
4. 강사가 끝난 수업을 지우면 그 수업이 만든 Docker 자원과 DB 기록이 남지 않는다.
5. 강사가 학생 한 명의 컨테이너를 재시작하거나, 학생 한 명을 지운다.

### 실패로 보는 경우

- 다른 학생이 이름만 알고 남의 세션에 들어가는 경우 (PIN 초기화 직후는 예외, 4.3 참고)
- 삭제 기능이 다른 수업이나 다른 학생, 또는 이 서버가 만들지 않은 Docker 자원을 지우는 경우
- 재개나 되찾기가 기존 볼륨 대신 빈 볼륨을 붙여 학생 코드가 사라진 것처럼 보이는 경우

## 4. 세션 되찾기

### 4.1 입장 요청

`POST /api/join`의 본문에 `pin`을 추가한다: `{entryCode, name, pin}`.

- PIN은 숫자 정확히 4자리다. 아니면 400.
- 수업이 READY가 아니면 지금처럼 거절한다.
- 이름은 앞뒤 공백을 지우고 비교한다. 영문은 대소문자를 구분하지 않는다. 한 수업 안에서 이름은 겹칠 수 없다.

| 상황 | 동작 | 응답 |
| --- | --- | --- |
| 그 수업에 같은 이름이 없음 | 새 세션을 만들고 PIN을 저장한다 (지금의 입장 흐름 + PIN) | 201 `{token, resumed:false}` |
| 같은 이름이 있고 PIN이 맞음 | 원래 세션으로 돌아간다 (4.2) | 200 `{token, resumed:true}` |
| 같은 이름이 있고 PIN이 틀림 | 실패 횟수를 올린다 | 403 `{error}`. 남은 횟수를 알려 준다 |
| 같은 이름이 있고 잠겨 있음 | 확인하지 않는다 | 429 `{error}`. 몇 분 뒤 가능한지 알려 준다 |
| 같은 이름이 있고 PIN이 비어 있음 (초기화됨, 또는 이 기능 전에 만든 세션) | 받은 PIN을 새 PIN으로 저장하고 원래 세션으로 돌아간다 | 200 `{token, resumed:true}` |

- PIN은 BCrypt 해시로 저장한다. 평문은 저장하거나 로그에 남기지 않는다.
- 5번 연속 틀리면 그 세션의 PIN 확인을 5분 잠근다. 맞히면 실패 횟수를 0으로 되돌린다.
- 4자리 PIN은 경우의 수가 1만 개라 잠금이 없으면 무작위 대입으로 뚫린다. 잠금이 그 방어선이다.

### 4.2 원래 세션으로 돌아갈 때

1. **토큰을 새로 발급한다.** 예전 토큰은 더 이상 쓸 수 없다. 공용 PC에 남은 예전 학생 화면이 계속 열리지 않게 하려는 것이다. 학생 화면은 이미 404를 받으면 폴링을 멈춘다.
2. 컨테이너가 꺼져 있으면 켠다. 컨테이너가 Docker에서 사라졌으면 **그 세션의 기존 볼륨 이름으로** 새 컨테이너를 만든다. 학생 코드는 볼륨에 있으므로 그대로 이어진다.
3. IDE 비밀번호는 바꾸지 않는다.

### 4.3 PIN 초기화

- 강사가 대시보드에서 학생의 "PIN 초기화"를 누르면 그 세션의 PIN 해시, 실패 횟수, 잠금을 비운다.
- 다음에 그 이름으로 들어오는 사람이 새 PIN을 정하고 원래 세션을 받는다. 강사가 그 학생에게 바로 다시 입장하라고 말하는 상황을 전제로 한다. 초기화와 재입장 사이에 다른 학생이 그 이름을 먼저 쓰면 세션을 가져갈 수 있다. 강사가 직접 누르는 동작이라 이 위험을 받아들인다.

### 4.4 화면

- `join.html`에 PIN 입력칸을 추가한다. 안내 문구: "처음 입장하면 PIN을 새로 정하고, 다시 들어올 때는 처음 정한 PIN을 입력하세요."
- 학생 화면 위쪽에 "다시 들어올 때는 입장 코드, 이름, PIN이 필요합니다"를 보여 준다. PIN 자체는 다시 보여 주지 않는다.

## 5. 수업 재개

- `POST /api/courses/{id}/resume` (강사 인증). ENDED가 아니면 409.
- 수업 상태를 ENDED에서 READY로 바꾼 뒤, 컨테이너 기록이 있는 학생 세션마다 4.2의 2번과 같은 방법으로 컨테이너가 돌게 한다.
- 컨테이너를 켜면 호스트 포트가 바뀔 수 있다. 다시 읽어 저장한다. 기존 `SessionService.restartContainer`가 이미 이렇게 한다.
- 한 학생이 실패해도 나머지는 계속한다. 응답은 200 `{started, failed}`.
- 재개 뒤에는 입장, 도움 요청, 점검, 에이전트가 지금 READY 수업과 똑같이 동작한다.
- 대시보드에서 ENDED 수업에 "수업 재개" 버튼을 보여 준다.

## 6. 수업 삭제

- `DELETE /api/courses/{id}` (강사 인증), 본문 `{confirmName}`.
  - `confirmName`이 수업 이름과 정확히 같지 않으면 400.
  - 수업이 ENDED나 FAILED가 아니면 409. FAILED는 발급에 실패한 수업이라 학생과 컨테이너가 없다. 강사가 치울 수 있게 함께 허용한다 (제가 정한 것).
- 지우는 순서:
  1. 학생 세션마다 컨테이너를 강제로 지우고, 그 세션의 볼륨을 지운다.
  2. 수업 이미지를 지운다. `DockerGateway`에 이미지 삭제 메서드를 추가한다.
  3. 서버 작업 폴더 `{dataDir}/courses/{id}`를 지운다.
  4. DB에서 그 수업의 에이전트 조치, 도움 요청, 점검 기록, 로컬 설치, 학생 세션, 수업 행을 외래 키 순서대로 지운다.
- **지울 대상은 DB에 기록된 이름과 ID로만 정한다.** 접두사로 훑어서 지우지 않는다. 이 서버가 만들지 않은 컨테이너나 볼륨은 절대 건드리지 않는다.
- Docker 자원 하나를 지우다 실패하면, 이미 없는 경우는 성공으로 보고, 그 밖의 실패는 기록하고 계속 진행한다. 응답은 200 `{removedContainers, removedVolumes, failures:[...]}`. 실패가 있어도 DB 기록은 지운다. 실패 목록에 남은 자원 이름을 담아 강사가 직접 치울 수 있게 한다.
- 화면: 대시보드의 ENDED·FAILED 수업에 "수업 삭제"를 둔다. 수업 이름을 입력하는 칸이 정확히 일치할 때만 버튼이 켜진다. 삭제가 끝나면 `instructor.html`로 돌아간다.

## 7. 학생 개별 관리

### 7.1 컨테이너 재시작

- `POST /api/courses/{id}/sessions/{sid}/restart` (강사 인증).
- 수업이 READY가 아니면 409. 그 학생에게 에이전트가 실행 중이면 409.
- 4.2의 2번과 같은 방법으로 컨테이너를 다시 켠다. 응답 200 `{ok}`.

### 7.2 학생 삭제

- `DELETE /api/courses/{id}/sessions/{sid}` (강사 인증). 세션이 그 수업 소속이 아니면 404.
- 그 학생에게 에이전트가 실행 중이면 409.
- 컨테이너와 그 세션의 볼륨을 지우고, 그 세션의 에이전트 조치, 도움 요청, 점검 기록, 로컬 설치, 세션 행을 지운다. Docker 실패 처리는 6장과 같다.
- 화면: 대시보드 학생 행에 "삭제" 버튼을 두고, 두 번 눌러야 실행한다 (기존 "수업 종료"와 같은 방식).

### 7.3 PIN 초기화

- `POST /api/courses/{id}/sessions/{sid}/reset-pin` (강사 인증). 204. 4.3의 동작.
- 화면: 대시보드 학생 행에 "PIN 초기화" 버튼.

## 8. 지켜야 하는 기존 규칙

- 학생 세션 필드는 담당 컬럼만 갱신하는 업데이트로 쓴다 (기존 규칙 R13). PIN 해시, 실패 횟수, 잠금 시각, 토큰 교체도 같다.
- 강사 API는 HTTP Basic 인증, 학생 API는 토큰 경로를 유지한다.
- 응답과 로그에 토큰, IDE 비밀번호, PIN, PIN 해시를 남기지 않는다.
- 화면은 지금처럼 서버 문자열을 텍스트로만 그린다.
- 통합 테스트는 테스트 전용 접두사와 인메모리 DB를 쓴다. 실제 수업, 컨테이너, 볼륨을 건드리지 않는다.

## 9. 검증

1. **자동 테스트:** 입장 표의 다섯 경우, 잠금과 해제, PIN 초기화 뒤 재입장, 토큰 교체 뒤 예전 토큰 404, 재개 상태 전이, 삭제 확인 이름 불일치, 상태별 409, 삭제 범위(다른 수업 자원을 지우지 않음), 학생 삭제 시 에이전트 실행 중 409.
2. **통합 테스트 (실제 Docker):** 학생 입장 → 파일 작성 → 수업 종료 → 재개 → 같은 파일이 남아 있음. 컨테이너를 `docker rm -f`로 지운 뒤 같은 이름과 PIN으로 재입장 → 새 컨테이너에 같은 파일. 수업 삭제 뒤 그 수업의 컨테이너, 볼륨, 이미지가 없음.
3. **실제 흐름:** 서버를 띄우고 브라우저 두 개로, 학생이 탭을 닫았다가 다른 브라우저에서 이름과 PIN으로 돌아오는 시연을 확인한다.

## 10. 검토 뒤 정한 것 (제가 정한 것)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 볼륨이 사라진 상태에서 컨테이너를 다시 만들 때 | `DockerGateway`에 볼륨 존재 확인을 추가한다. 볼륨이 없으면 새 빈 볼륨으로 컨테이너를 만들되, 학생 화면에 "이전 작업 공간을 찾지 못해 새로 만들었습니다"를 보여 주고 대시보드에 강사 도움 필요("작업 공간 유실")로 올린다. 재개에서는 이 학생을 `recreatedEmpty`로 따로 센다. | 조용히 빈 볼륨을 붙이는 실패(3장)는 막고, 학생이 아예 못 들어오는 상황도 막는다. 누군가 `docker volume rm`을 직접 쳤을 때만 생기는 드문 경우다. |
| 같은 수업에 같은 이름의 세션이 이미 여러 개일 때 (이 기능 전에 생긴 중복) | 가장 최근에 만든 세션(가장 큰 ID)을 돌려준다. 나머지는 강사가 "학생 삭제"로 정리한다. 새 입장의 이름 중복은 정규화한 이름 컬럼과 서버 쪽 확인으로 막는다. 예전 행은 정규화 이름이 비어 있어도 된다. | 학생이 마지막으로 쓰던 세션일 가능성이 가장 높다. DB 고유 제약을 예전 중복 행 때문에 걸 수 없는 문제를 피한다. |
| 수업 단위 작업이 겹칠 때 | 재개, 종료, 삭제는 수업마다 한 번에 하나만 실행한다(서버 메모리의 수업별 잠금 + 상태 조건부 갱신). 수업 삭제는 그 수업에 에이전트가 하나라도 실행 중이면 409. | 학생 삭제·재시작과 같은 기준이다. |
| 재개 중 점검과의 충돌 | 재개는 수업이 ENDED인 동안 컨테이너를 먼저 켜고 health 확인을 병렬로 기다린 뒤(전체 60초 상한), 마지막에 READY로 바꾼다. 응답은 `{started, unhealthy, recreatedEmpty, failed}`. 이 경로는 READY 전제 조건이 있는 `restartContainer`를 거치지 않고 Docker 시작과 포트 갱신을 직접 한다. | 점검 스케줄러는 READY 수업만 보므로, 켜지는 중인 컨테이너를 "IDE 중단"으로 보고 에이전트를 부르는 일이 없다. |
| 토큰 교체와 로컬 설치 링크 | 예전 토큰으로 만든 설치 명령과 zip 링크도 함께 끊긴다. 학생은 새 학생 화면에서 다시 받는다. | 토큰 하나로 묶인 권한을 한 번에 회수하는 쪽이 단순하고 안전하다. |

## 11. 빌더에게 맡기는 것

- 서비스와 클래스 분리 방식. 다만 기존 리뷰에서 `CourseService`가 커졌다는 지적이 있었으므로, 수명 관리는 별도 서비스로 두는 편을 권한다.
- 오류 문구의 정확한 표현 (한국어, 짧게)
- 대시보드 버튼 배치
