# 새 화면(클라이언트) 도입 설계

- 작성일: 2026-11-05
- 기준 문서: `docs/specs/2026-11-04-prototype-design.md`, `docs/specs/2026-11-05-session-lifecycle-design.md`, `docs/specs/2026-11-05-ide-help-panel-design.md`. 여기 없는 내용은 기준 문서와 현재 코드를 따른다.
- 출발 코드: `SWUNION-12/client` 커밋 `39244a7` (Next.js 16.4.5, React 19.3.0, Astryx 0.7.8)

## 1. 왜 하는가

지금 강사·학생 화면은 `src/main/resources/static`의 HTML 네 장이다. 팀이 만든 클라이언트는 디자인 시스템(Astryx)을 쓰고, 진행 표시, 학생 검색·필터, 도움 결과 화면 같은 기능이 더 있다. 이 클라이언트를 우리 저장소로 가져와 **우리 서버에 맞게 고쳐서** 화면으로 쓴다.

## 2. 사용자가 정한 것

| 항목 | 결정 |
| --- | --- |
| 원칙 | **클라이언트를 그대로 쓰지 않는다.** 출발 재료로 가져와 디자인과 기능을 우리가 고친다. |
| 기준 | **우리 서버가 기준이다.** 클라이언트가 기대하는 API에 서버를 맞추지 않고, 클라이언트를 서버에 맞춘다. 서버에는 작은 필드만 더한다. |
| 위치 | **prototype-server 저장소 안으로 가져온다.** |
| 배포 | 정적 빌드로 만들어 Spring이 같은 주소에서 내보낸다. Caddy HTTPS 구성은 그대로다. |
| 서비스 이름 | **코딩책상** |
| 용어·경로 | 학생이 입장할 때 쓰는 코드는 화면과 서버 문구 모두 **"수업 코드"**. 강사 화면 경로는 **`/instructor`** (사용자 결정) |
| 강사 로그인 | **로그인 페이지 + 세션 로그인** (브라우저 기본 로그인 창 대신. 6-1절) |
| 지킬 것 | 우리 PIN 모델(해시 저장, 5회 실패 잠금, 재입장 시 토큰 교체), 수업 재개·삭제, 학생 재시작·삭제, PIN 초기화, IDE 안 실습 도우미 |

## 3. 목표와 실패 기준

### 목표

1. 지금 HTML 화면이 하는 일을 새 화면이 모두 한다(5절 목록). 확인이 끝나면 HTML 네 장을 지운다.
2. `./gradlew bootJar` 한 번으로 새 화면이 jar에 들어간다. 배포 절차는 지금과 같다.
3. 클라이언트에 이미 있는 좋은 기능을 살린다: 수업 준비 진행 표시, 수업 코드·입장 링크 복사, 학생 필터·검색, 반복 오류 카드, 도움 결과의 분류 뱃지와 "확인할 곳" 상자, 탭이 숨겨지면 느려지는 주기 조회.

### 실패로 보는 경우

- PIN 평문이 서버 응답이나 화면 어디에든 나오는 경우
- 강사 계정 정보가 브라우저 저장소(sessionStorage, localStorage)에 남는 경우
- 강사 인증 없이 강사 화면의 데이터가 보이는 경우
- 다른 사이트가 로그인한 강사의 브라우저로 강사 API를 부를 수 있는 경우(CSRF)
- 재입장으로 토큰이 바뀐 뒤 옛 탭이 계속 동작하는 경우(지금처럼 "다시 입장" 안내가 나와야 한다)
- 학생 화면이 서버 오류 문구를 HTML로 그리는 경우(모델과 학생 환경에서 온 글은 텍스트로만 그린다)

## 4. 클라이언트에서 고치거나 뺄 것

| 클라이언트 지금 | 바꾼 뒤 |
| --- | --- |
| PIN을 IDE 비밀번호로 쓰고 평문 저장, 대시보드가 `students[].pin`을 보여 줌 | PIN은 입장용으로만 쓴다. 대시보드는 `pinSet`으로 "설정됨/미설정"만 보인다. IDE 비밀번호는 지금처럼 따로 있다. |
| `reset-pin`이 새 PIN `{pin}`을 돌려받아 토스트로 보여 줌 | 서버는 204. "다음 입장 때 학생이 PIN을 새로 정합니다"라고 안내한다. |
| 강사 로그인 페이지 + `sessionStorage`에 Basic 계정 보관 | 로그인 페이지 디자인은 살리고, 계정 보관은 뺀다(`auth.ts`, `use-credentials.ts` 삭제). 서버 세션 로그인으로 바꾼다(6-1절). |
| IDE를 숨은 폼으로 자동 로그인 | 자동 로그인을 뺀다. IDE는 화면 안 iframe으로 띄우고, 머리말에 IDE 비밀번호와 복사 버튼, "새 탭에서 열기"를 둔다. 학생은 처음 한 번 비밀번호를 붙여 넣는다. **(작업 중 정함)** |
| 입장 응답 `rejoined` | 우리 서버의 `resumed`(새 입장 201, 재입장 200). 403(PIN 틀림, 남은 횟수 안내), 429(잠김), 400(형식) 문구는 서버가 준 그대로 보인다. |
| 학생 재시작 204, 삭제 204 | 우리 서버: 재시작 200 `{ok}`, 삭제 200 `{removedContainers, removedVolumes, failures}`, 도움 처리 중이면 409. 실패와 409 문구를 보인다. |
| 수업 설정 탭: 이름·정원 변경(`PATCH`) | 정원과 이름 변경은 뺀다(서버에 없음). 설정 탭은 **수업 종료, 수업 재개, 수업 삭제(수업 이름 확인 입력)** 와 수업 정보 보기로 바꾼다. |
| 동적 경로 `/lab/[token]`, `/instructor/courses/[id]/...` | 정적 빌드에 맞게 쿼리로 바꾼다: `/lab?t=<토큰>`, `/instructor/course?id=<id>`, 설정 탭은 `&tab=settings`. |
| 목업 서버(`mock/`), `API_CONTRACT.md`, 목업용 `dev` 스크립트 | 뺀다. 개발 중에는 `pnpm dev`가 로컬 Spring(8080)으로 `/api`, `/l`을 넘긴다. |
| Python 버전 목록(uv 0.11.32 기준 고정) | 실제로 확인한 범위 3.8~3.14만 보인다. |
| `SERVICE_NAME = "[서비스명]"` | **"코딩책상"** (사용자 결정). 페이지 제목에도 쓴다. IDE 안 패널 이름 "실습 도우미"는 그대로 둔다. |

## 5. 새 화면이 해야 하는 일 (지금 HTML 기준 목록)

**강사**

- 수업 목록(상태, 수업 코드, 학생 수), 수업 만들기(이름, Python 버전, 패키지)
- 수업 준비 진행(LOCKING → BUILDING → READY, 경과 시간), FAILED면 `errorSummary`
- 학생 목록: 환경 상태, 불일치 문구(`issues`), 스펙에 없는 패키지(`extras`), 내 PC 상태(`local`), 도움 필요와 이유, 최근 에이전트 기록, 시작 시간, PIN 설정 여부
- 반복 오류 카드
- 학생별: 처리 완료(resolve), 재시작, PIN 초기화, 삭제(되돌릴 수 없다는 확인)
- 수업 종료, 재개, 삭제(수업 이름 입력 확인)
- 수업 코드 복사, 입장 링크(`/join?code=...`) 복사

**학생**

- 입장: 수업 코드, 이름, PIN. 재입장 성공이면 "이전 작업 공간으로 돌아왔습니다" 안내
- 실습 화면: 환경 상태와 불일치 문구, IDE(iframe, 비밀번호 복사, 새 탭), 작업 공간 유실(`workspaceLost`) 안내
- 도움 요청과 결과(분류 뱃지, 설명, 확인할 곳), 강사 호출
- 수업 종료 상태: IDE 대신 종료 안내와 코드 zip 내려받기
- 내 PC로 이어가기: OS별 진단 명령, 진단 결과 제출, 설치 명령과 스크립트 보기, 검증 결과 제출, 코드 zip
- 토큰이 바뀌었거나 없는 세션(404)이면 "다시 입장" 화면

## 6. 서버에 더할 것

| 응답 | 더할 필드 | 쓰는 곳 |
| --- | --- | --- |
| `GET /api/s/{token}` (공통 상태 응답) | `courseStatus` | 종료 안내, 도움 요청 버튼 잠금 |
| 같은 응답의 `latestHelp` | `classification` (`ENV`, `CODE`, `OUT_OF_SCOPE`, `UNKNOWN`, 없으면 null) | 도움 결과 분류 뱃지. 그 도움 요청을 처리한 에이전트 기록에서 가져온다. |
| `GET /api/courses`, `GET /api/courses/{id}` | `studentCount` | 수업 목록의 학생 수 |

### 6-1. 강사 로그인 (사용자 결정으로 추가)

| 항목 | 내용 |
| --- | --- |
| 로그인 | `POST /api/auth/login` (폼 필드 `username`, `password`) → 성공 204와 세션 쿠키, 실패 401 `{error: "아이디 또는 비밀번호를 확인해 주세요."}` |
| 로그아웃 | `POST /api/auth/logout` → 204 |
| 확인 | `GET /api/auth/me` → 200 `{username}`, 로그인 전 401 |
| 로그인 전 강사 API | 401 `{error}`. `WWW-Authenticate`를 보내지 않아 브라우저 로그인 창이 뜨지 않는다. HTTP Basic은 끈다. |
| 로그인 전 강사 화면 | `/instructor`, `/instructor/**`는 `/instructor/login?next=<원래 경로>`로 보낸다. `/instructor/login`은 공개. 화면은 `next`가 `/instructor`으로 시작할 때만 따른다(다른 사이트로 보내지 않음). |
| CSRF | 켠다. 쿠키 `XSRF-TOKEN` → 헤더 `X-XSRF-TOKEN` 방식. 학생 토큰 경로(`/api/join`, `/api/s/**`, `/l/**`)와 IDE 확장 경로(`/api/ide/**`)는 쿠키 로그인을 쓰지 않으므로 뺀다. |
| 세션 쿠키 | HttpOnly, SameSite=Lax, HTTPS에서는 Secure(Caddy가 보내는 `X-Forwarded-Proto`를 믿는다). 로그인하면 세션 ID를 새로 만든다. 세션은 마지막 요청 뒤 8시간이 지나면 끝난다(유휴 시간 제한이라 절대 상한이 아니다. 탭을 열어 둔 채 대시보드가 계속 조회하면 이어진다). 서버를 다시 켜면 다시 로그인한다. |
| 화면 | 클라이언트의 로그인 페이지 디자인을 살린다. 강사 화면 머리말에 로그아웃. 강사 API가 401이면 로그인 페이지로 보낸다. |

그 밖의 서버 API는 바꾸지 않는다. 보안 설정은 강사 화면 경로를 바꾼다: `/instructor`, `/instructor/**`(정적 빌드 파일 포함)와 `/api/courses/**`만 인증, 옛 `/instructor.html`, `/dashboard.html` 규칙은 HTML을 지울 때 함께 지운다.

## 7. 구성

```
web/                      ← 가져온 클라이언트 (Next.js, output: export)
  src/app/join, lab, instructor, instructor/new, instructor/course, instructor/login
  out/                    ← pnpm build 결과 (git에 넣지 않음)
build.gradle              ← bootJar가 web을 빌드해 out/을 static/으로 넣는다
src/main/java/.../config  ← 확장자 없는 경로(/join)를 join.html로 내보내는 설정
```

- 정적 파일은 Spring이 내보낸다. `/join`처럼 확장자 없는 주소가 `join.html`로 가야 한다. `/`는 `/join`으로 보낸다.
- `./gradlew test`는 pnpm 없이 돈다. 웹 빌드는 `bootJar`에서만 한다.
- 로컬 개발: Spring을 8080에 띄우고 `web/`에서 `pnpm dev`. 배포 문서의 로컬 준비물에 pnpm을 더한다.

## 8. 확인 방법

- 서버: 새 필드 3개의 단위 테스트, 보안 규칙 테스트(강사 경로 401, 학생 경로 200), 확장자 없는 경로 테스트. 기존 테스트 통과.
- 화면: `pnpm lint`, 타입 검사, `pnpm build` 통과.
- 실제 실행: 로컬 Spring + Docker에서 헤드리스 Chrome으로 강사 수업 만들기 → 학생 입장 → 실습 화면에 IDE가 뜸 → 도움 요청 → 대시보드에 학생이 보임 → PIN 초기화·재시작·삭제 → 수업 종료·재개·삭제까지 돈다. 화면 캡처를 남긴다.
- 팀 서버 배포는 위가 끝난 뒤 따로 허락을 받고 한다.

## 9. 하지 않는 것

- 강사 로그인 시도 횟수 제한. 알려진 한계로 남긴다.
- 정원(capacity), 수업 이름 변경 API
- 디자인 전면 수정. 클라이언트 디자인을 바탕으로 우리 기능에 필요한 곳만 고친다.

## 10. 만드는 사람에게 맡기는 것

- Gradle과 pnpm을 잇는 방법(작업 이름, 최신 여부 판단)
- 확장자 없는 경로를 처리하는 Spring 쪽 구현 방식
- 화면 문구 세부, Astryx 컴포넌트 선택
