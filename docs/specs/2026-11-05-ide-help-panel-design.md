# IDE 안 도움 패널 설계

- 작성일: 2026-11-05
- 기준 문서: `docs/specs/2026-11-04-prototype-design.md`, `docs/specs/2026-11-05-session-lifecycle-design.md`. 여기 없는 내용은 기준 문서와 현재 코드를 따른다.

## 1. 왜 만드는가

지금 학생은 IDE(code-server)에서 코딩하다 막히면 브라우저 탭을 바꿔 학생 화면으로 가서 도움을 요청한다. 오류를 복사해 다른 탭에 붙여 넣고, 답을 보려면 다시 탭을 오간다. 학생이 코딩하는 화면 안에서 바로 도움을 받게 한다.

## 2. 사용자가 정한 것

| 항목 | 결정 |
| --- | --- |
| 옮길 기능 | **도움 요청, 강사 호출, 환경 상태**(패키지가 정상인지, 복구 중인지) 세 가지 |
| 모양 | 지금 학생 화면의 기능을 그대로 쓰되, code-server(VS Code) 화면에 맞춘 모양 |
| 옮기지 않을 것 | IDE 주소·비밀번호, "내 PC로 이어가기"(설치 명령, 코드 zip) |

## 3. 목표와 실패 기준

### 목표

1. 학생이 IDE 왼쪽 사이드바의 "실습 도우미" 패널에서 환경 상태를 본다. 정상, 불일치(무엇이 빠졌는지), 복구 중이 구분된다.
2. 패널에서 오류 내용을 넣고 도움을 요청하면, 지금 학생 화면과 같은 결과(설명, 처리 상태, 강사 전달)가 패널에 나온다.
3. 패널에서 강사를 호출하면 대시보드에 지금처럼 "학생 호출"이 뜬다.
4. 편집기나 터미널에서 오류를 드래그해 선택한 뒤 명령 하나로 도움 요청 입력칸에 넣는다. **(제가 정한 것: 앞서 "덤"으로 제안한 기능)**

### 실패로 보는 경우

- 패널이 다른 학생의 상태를 보거나, 다른 학생 이름으로 도움을 요청할 수 있는 경우
- 패널 때문에 IDE가 느려지거나, 서버가 꺼졌을 때 IDE 자체가 오류로 막히는 경우
- 학생이 PIN으로 세션을 되찾은 뒤(토큰 교체) 패널이 끊기는 경우

## 4. 구성

```
학생 브라우저 ── code-server (학생 컨테이너)
                   └ 확장 "실습 도우미" (Node 쪽 코드)
                        │ HTTP, 헤더 X-Session-Key
                        v
                 Spring Boot 서버  /api/ide/...  → 기존 HelpService, 세션 상태
```

- 화면(webview)은 서버를 직접 부르지 않는다. 확장의 Node 쪽 코드가 서버를 부르고, webview와는 메시지로 주고받는다. CORS와 webview 보안 정책 문제를 피하려는 것이다.
- 학생 화면(`student.html`)의 기능은 그대로 둔다. 확장이 실패해도 학생 화면으로 도움을 요청할 수 있다. **(제가 정한 것)**

## 5. 인증: 컨테이너 키

학생 토큰은 PIN 되찾기 때마다 바뀌므로 컨테이너 안에 넣어 둘 수 없다. 세션마다 **바뀌지 않는 컨테이너 키**를 따로 둔다.

- `StudentSession`에 `ideKey`(무작위 32바이트, 16진 64자)를 추가한다. 새 세션을 만들 때 발급한다. 이 기능 전에 만든 세션은 키가 없다.
- 컨테이너를 만들 때 환경변수 두 개를 넣는다.
  - `SWUNION_IDE_KEY`: 이 세션의 컨테이너 키
  - `SWUNION_SERVER_URL`: 컨테이너에서 서버에 닿는 주소. 설정값 `lab.server-url-for-containers`, 기본 `http://host.docker.internal:8080`
- 리눅스 Docker에서도 `host.docker.internal`이 풀리도록 컨테이너에 `host.docker.internal:host-gateway` 호스트 항목을 넣는다.
- **이 기능은 새 기본 이미지로 만든 수업부터 적용한다. (제가 정한 것)** 수업 이미지는 수업을 만들 때 기본 이미지 위에 빌드되므로, 예전 수업의 이미지에는 확장이 없다. 예전 수업을 고치려면 수업 이미지를 다시 빌드하는 기능이 따로 필요한데, 지금 있는 수업은 시험용 데이터라 그 비용을 들이지 않는다.
  - 기본 이미지 태그를 `swunion/lab-base:2`로 올리고 `lab.base-image` 기본값과 `scripts/build-base-image.sh`도 `:2`로 바꾼다. 예전 수업은 `:1` 기반 이미지를 그대로 쓰고, 학생 화면으로 도움을 요청한다.
  - 키 없는 세션을 위해 컨테이너를 다시 만드는 경로는 만들지 않는다. 재시작, 재개, 되찾기, 에이전트 `restart_ide`의 동작은 바꾸지 않는다.
  - 새 수업의 세션은 만들 때 키를 받고, 컨테이너를 다시 만들 때(되찾기·재개의 재생성 경로)도 같은 키를 환경변수로 다시 넣는다.
- 컨테이너 키는 그 학생의 컨테이너 안에서만 보인다. 학생 자신이 보는 것은 문제가 없다. 키로 할 수 있는 일은 그 학생 자신의 상태 조회, 도움 요청, 강사 호출뿐이다.
- 응답과 로그에 키를 남기지 않는다.

## 6. 서버 API

모두 헤더 `X-Session-Key`로 세션을 찾는다. 키가 없거나 틀리면 401 `{error}`. 강사 Basic 인증과 학생 토큰 경로와는 별개다.

| Method | 경로 | 동작 |
| --- | --- | --- |
| GET | `/api/ide/status` | `{name, courseName, envStatus, issues, needsHelp, latestHelp}`. 지금 `GET /api/s/{token}`에서 IDE 주소·비밀번호를 뺀 것 |
| POST | `/api/ide/help` | 본문 `{errorText}`. 지금 `POST /api/s/{token}/help`와 같은 동작과 응답(202, 409 처리 중) |
| POST | `/api/ide/escalate` | 지금 `POST /api/s/{token}/escalate`와 같음 |

- 수업이 READY가 아니면 지금 학생 API와 같은 오류를 준다.
- 컨테이너 키로 찾는 쿼리는 키 비교에 상수 시간 비교를 쓴다. **(제가 정한 것)**

## 7. 확장

- `docker/lab-base/` 안에 확장 소스를 두고, 기본 이미지를 빌드할 때 설치한다. 외부 마켓플레이스에 올리지 않는다.
- npm 의존성 없이 순수 JavaScript로 쓴다. 빌드 단계를 두지 않는다. code-server가 쓰는 Node의 내장 `http`만 쓴다.
- 활동 막대(왼쪽 아이콘 줄)에 "실습 도우미" 아이콘을 두고, 누르면 사이드바에 webview 패널이 열린다.
- 패널 내용 (위에서부터):
  1. **환경 상태:** 정상 / 불일치(대시보드와 같은 한국어 문구로 항목 나열) / 복구 중. 서버에 닿지 않으면 "서버에 연결하지 못했습니다"
  2. **도움 요청:** 오류 입력칸, "도움 요청" 버튼, 최근 요청의 처리 상태와 설명. 강사에게 넘어갔으면 "강사에게 전달했습니다"
  3. **강사 호출** 버튼
- 모양은 VS Code 테마 색 변수(`--vscode-foreground`, `--vscode-button-background` 등)를 써서 밝은 테마와 어두운 테마에 맞는다.
- 갱신: 패널이 보일 때만 5초마다 상태를 읽는다. 숨겨지면 멈춘다. 요청이 겹치지 않게 한다.
- 선택한 오류 보내기: 명령 "실습 도우미: 선택한 내용으로 도움 요청"을 편집기 우클릭 메뉴와 터미널 우클릭 메뉴에 넣는다. 편집기는 선택 영역을, 터미널은 선택한 내용을 복사해 읽은 뒤 패널 입력칸에 넣고 패널을 연다. 바로 보내지는 않고 학생이 확인 후 보낸다.
- 서버 문자열은 텍스트로만 그린다. webview에 콘텐츠 보안 정책을 걸고, 외부 리소스를 불러오지 않는다.
- 서버가 꺼져 있거나 키가 없어도 확장이 예외로 IDE를 방해하지 않는다.

## 8. 지켜야 하는 기존 규칙

- 학생 세션 필드는 담당 컬럼만 갱신하는 업데이트로 쓴다 (R13). `ideKey` 발급도 같다.
- 학생 컨테이너 안 명령과 에이전트 도구 허용 목록은 바꾸지 않는다.
- 통합 테스트는 테스트 전용 접두사와 인메모리 DB를 쓰고, 실제 수업 자원을 건드리지 않는다.
- 기본 강사 비밀번호 경고는 그대로 유지한다. 이 기능은 컨테이너에서 서버에 닿는 길을 공식으로 쓰는 것이므로, 학생에게 IDE를 주기 전에 강사 비밀번호를 바꿔야 한다는 문서 안내가 더 중요해진다.

## 9. 검증

1. **자동 테스트:** 키 인증(없음, 틀림, 다른 세션), 상태 응답 필드, 도움 요청과 409, 강사 호출, 새 세션의 키 발급, 컨테이너 환경변수와 호스트 항목(새로 만들 때와 재생성할 때 모두 같은 키).
2. **통합 테스트 (실제 Docker):** 새 컨테이너 안에서 `SWUNION_IDE_KEY`와 `SWUNION_SERVER_URL`로 서버의 `/api/ide/status`를 호출해 200을 받는다(컨테이너에서 서버로 실제로 닿는지 확인).
3. **실제 흐름:** 서버를 띄우고 헤드리스 브라우저로 IDE에 로그인해 패널을 연다. 환경 상태 표시, 오류 선택 후 도움 요청, 강사 호출이 대시보드에 반영되는 것을 확인한다. 패키지를 지워 "복구 중"이 패널에 보이는지도 본다.

## 10. 빌더에게 맡기는 것

- 확장 파일 구조와 이름, 아이콘
- 확장을 이미지에 설치하는 방법(vsix로 묶어 설치하거나 확장 폴더에 직접 넣기). 어느 쪽이든 code-server 4.144.0에서 실제로 로드되는지 확인해야 한다.
- 패널 문구의 세부 표현 (한국어, 짧게)
